# TRADERS · 트레더 기능 안내

트레이더스의 대용량 상품을 여러 사용자가 함께 소분 예약하는 모바일 웹 프로토타입입니다. 상품 추천과 투표도 지원합니다. 화면과 흐름은 정적 웹으로 제공하고, 계정과 사용자 간 공유되는 예약 데이터는 Supabase에 저장합니다.

## 사용 흐름

```text
트레이더스 홈
  └─ 트레더
      ├─ 상품 탐색 / 검색
      │   └─ 상품 상세 → 소분 수량 선택
      │       ├─ 진행 중 모집에 참여 → 정원 충족 전까지 대기
      │       ├─ 마감 상품 대기 신청
      │       └─ 같은 상품의 새 모집 시작
      ├─ 커뮤니티 → 상품 추천 / 좋아요 투표
      ├─ 소분 예약 → 내 모집 참여 / 대기 / 확정 예약
      └─ 마이페이지 → 계정 확인 / 로그아웃
  └─ 모집 정원 충족 → 참여자 예약 확정 → 장바구니에 품목별 QR 표시
```

## 상품 탐색

- 상품 목록은 Supabase의 활성 상품을 읽어 구성합니다. 현재 화면에서 신선식품과 정육/수산을 탐색할 수 있습니다.
- 신선식품은 상품 카테고리별로, 정육/수산은 전체·정육·수산 유형과 상품 카테고리별로 좁혀볼 수 있습니다.
- 검색은 상품명, 카테고리, 유형, 중량을 대상으로 합니다.
- 상품 상세에는 판매가, 소분 단가, 선택 수량, 모집 진행 수량, 평점 등의 정보를 표시합니다. 수량 선택에 따라 예상 금액을 계산합니다.
- 상품 정보와 후기 예시는 화면 표시용 데이터입니다. 실제 재고, 결제 가격 검증, 구매 후기 시스템과 연결되어 있지 않습니다.

## 공동 소분 모집 규칙

1. 로그인한 사용자가 진행 중인 상품 모집에서 소분 수량을 선택해 참여합니다.
2. 참여 수량은 하나의 공유 모집에 반영됩니다. 정원이 남아 있는 동안 예약은 `pending` 상태이고 장바구니나 QR에 표시되지 않습니다.
3. 모집 수량이 정원에 도달하면 해당 모집의 참여 예약을 `confirmed`로 바꾸고, 참여자의 장바구니에서 예약과 QR을 보여줍니다.
4. 사용자는 마이페이지의 **소분 예약**에서 모집 참여, 마감 대기, 확정 예약 건수를 확인할 수 있습니다. 모집 참여 취소와 대기 취소도 이 화면에서 할 수 있습니다.
5. 진행 중 모집이 없는 상품은 대기 신청할 수 있습니다. 같은 상품에는 사용자별 활성 대기 신청이 하나만 유지됩니다.
6. 대기 신청은 모집의 남은 수량에 들어갈 때 순서대로 승격됩니다. 대기 신청 수량이 남은 자리보다 크면 해당 차례에는 건너뛰고, 들어갈 수 있는 신청을 처리합니다.
7. 모집 마감 이후에는 상품 상세에서 대기를 걸거나 같은 상품의 새 모집을 시작할 수 있습니다. 새 모집이 열리면 대기자가 우선 배정되고, 자리가 남아 있으면 새 모집을 시작한 사용자도 참여할 수 있습니다.
8. 예약 취소는 확인 팝업을 거친 뒤 처리합니다. 취소로 빈 자리가 생기면 가능한 대기 신청자를 모집에 반영합니다. 화면에 취소 수수료 안내 문구가 있지만, 현재 프로토타입에서 실제 수수료 결제는 처리하지 않습니다.

QR은 `share_rounds`가 정원 충족 상태이고 예약도 확정된 경우에만 생성됩니다. QR은 예약 번호, 상품, 소분 수량, 금액을 담은 프로토타입 확인 코드이며 매장 시스템에서 실제 스캔·수령 검증하는 기능은 아직 없습니다.

## 커뮤니티

- 상품 추천 목록은 로그인하지 않아도 볼 수 있습니다.
- 로그인한 사용자는 상품명과 선택 설명을 등록할 수 있습니다. 상품명은 최대 100자, 설명은 최대 240자입니다.
- 로그인한 사용자는 추천별 좋아요를 등록하거나 취소할 수 있습니다. 동일 사용자는 추천 하나에 한 표만 가집니다.
- 목록은 투표 수가 많은 순, 같은 수일 때 최근 등록 순으로 표시됩니다.
- 새로고침 버튼으로 목록을 다시 불러옵니다. 추천 등록 직후에는 폼 입력을 비우고 갱신된 목록을 표시합니다.

## 계정과 마이페이지

- 이메일·비밀번호 가입과 로그인은 Supabase Auth를 사용합니다. 가입 시 이름을 저장하며, 세션은 브라우저 저장소에 보관합니다.
- 인증이 필요한 모집 참여, 커뮤니티 추천, 투표는 로그인 화면으로 안내합니다.
- 마이페이지는 이름과 이메일, 프로토타입 멤버십/혜택 정보, 커뮤니티·계정 메뉴, 로그아웃을 표시합니다.
- 쿠폰, 리뷰, 영수증, 멤버십 혜택 수치는 현재 예시 화면이며 실제 이마트 멤버십 서비스에서 읽어오지 않습니다. 계정 정보 설정 메뉴도 안내 메시지만 표시합니다.

## 데이터 공유와 동기화

여러 브라우저와 사용자가 같은 Supabase 프로젝트를 사용하므로 모집 수량, 예약, 대기, 커뮤니티 추천과 투표가 공유됩니다. 예약과 대기 행은 Supabase Auth 사용자 ID에 연결되고, RLS 정책으로 각 사용자가 자기 예약·대기 내역을 조회하도록 제한합니다.

- 상품: `products`
- 모집 진행: `share_rounds` 및 조회용 `share_round_progress`
- 예약: `share_orders`
- 대기열: `share_waitlist`
- 추천과 투표: `product_suggestions`, `suggestion_votes`

모집 참여, 새 모집 시작, 대기 신청, 대기 취소, 예약 취소는 SQL RPC에서 처리합니다. 이 방식으로 정원 확인과 예약 상태 변경을 데이터베이스 트랜잭션 안에서 수행합니다. 앱이 열려 있고 탭이 보일 때 공유 예약 상태를 약 7초마다 조회합니다.

주요 RPC:
- `join_share`: 진행 중 모집에 참여하고, 정원을 채우면 해당 모집 예약을 확정합니다.
- `join_share_waitlist`: 상품 대기열에 추가하거나 기존 대기 수량을 갱신합니다.
- `leave_share_waitlist`: 현재 사용자의 대기 신청을 취소합니다.
- `start_share_round`: 새 모집을 시작하고 대기자를 먼저 배정합니다.
- `cancel_share`: 현재 사용자 예약을 취소하고 가능한 대기 신청자를 반영합니다.
- `list_product_suggestions`: 추천 목록과 투표 수, 현재 사용자의 투표 여부를 반환합니다.

## 실행과 Supabase 준비

별도 앱 서버나 빌드 과정은 없습니다. Supabase 프로젝트에서 **SQL Editor**로 `supabase-setup.sql`을 실행하고, `supabase-config.js`의 프로젝트 URL과 브라우저용 공개 `anon`/`publishable` 키를 설정합니다. `service_role` 키는 브라우저 파일에 넣으면 안 됩니다. 인증 메일 확인 여부는 Supabase Auth 설정에 따릅니다.

정적 서버를 프로젝트 폴더에서 실행하려면:

```bash
python -m http.server 8000
```

- 앱: `http://localhost:8000/`
- 아이폰 프레임 미리보기: `http://localhost:8000/preview.html`

GitHub Pages는 저장소 설정에서 `main` 브랜치의 루트를 배포하도록 설정합니다. 배포된 `preview.html`은 사이트의 `/preview.html` 경로에서 열 수 있습니다.
